# 第一周：亲手让晨潮港船长移动

预算：5～8小时，按有效学习周计算。目标：自己实现并解释一段基础移动，能验证，也能修改。

## 打开后先观察

使用Unity2022.3.53f1c1打开WaveWarlord，打开 `Assets/_Game/Scenes/HarborLab.unity`。

场景已提供地面、墙、码头、仓库与告示板占位、橙色胶囊Captain和固定镜头。Captain上有CharacterController，没有移动脚本。按WASD暂时不移动是当前预期。

本周只做平地移动和墙体碰撞。完整重力、坡道、自由镜头和交互在后续R1任务中完善。

## 实现顺序

1. 用Input System建立Move动作，类型为Vector2，配置WASD的2D Vector组合绑定。
2. 观察不同按键读到的值。确认组合绑定是否已经规范化斜向输入。
3. 你在 `Assets/_Game/Scripts` 新建首个移动脚本，决定字段和函数怎样组织，再挂到Captain。
4. 先按世界坐标约定实现：W为+Z、D为+X。此阶段镜头固定且倾斜，移动方向不要求与屏幕上下完全重合；相机相对移动在下一任务加入。
5. 通过CharacterController完成移动碰撞。它不会自动替你施加重力；当前平地练习可以先保持出生高度，后续明确实现垂直速度和落地。
6. 运行下表，自己先定位一个问题，再接受代码审查。

首版可以只有一个小脚本。现代语法、模式数量和文件数量都不是验收指标。

## 验收

| 检查 | 操作与预期 | 实际结果 |
|---|---|---|
| 四方向 | W/A/S/D方向符合世界坐标约定，松开停止 | 未测 |
| 反向按键 | W与S同时按下，结果稳定且可解释 | 未测 |
| 斜向 | 同时长直线与斜向水平路程接近 | 未测 |
| 帧率 | 关闭VSync，分别限制30和120FPS；按实测帧率比较同时间路程 | 未测 |
| 碰撞 | 向Wall持续移动，不能穿墙；斜着贴墙行为可解释 | 未测 |
| 速度参数 | 速度加倍，无障碍同时间路程约加倍 | 未测 |
| 独立构建 | 通过WaveWarlord/R0/Build Windows打包并运行，输入可用 | 未测 |

测量在空旷地面从同一起点开始，记录实际时长、起终点和帧率。可各做3次3～5秒粗测，说明人工按键误差。目标帧率不等于实际帧率。先发现明显差异，再按需加入小型测量辅助；不要为了首周搭通用测试框架。

场景边缘目前没有完整边界保护；当前验证路线在地面与Wall附近。后续移动系统加入重力时，再处理地面之外的行为。
