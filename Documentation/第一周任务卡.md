## 开始前理解5件事（工作日零散时间，约40分钟）

1. **Input System的Action**：`InputAction`是什么、为什么要`Enable()`、`ReadValue<Vector2>()`返回什么、2D Vector组合绑定是什么。本工程只启用了新Input System，`Input.GetAxis`不可用。
2. **位移＝速度×时间**：`Time.deltaTime`的含义；速度单位用米/秒。
3. **`CharacterController.Move(motion)`**：参数是这一帧的位移，不是速度；它处理碰撞和沿墙滑动，但不施加重力。顺便看一眼`SimpleMove`的区别。
4. **Vector2到Vector3**：输入(x, y)对应世界(x, 0, z)；对归一化与限制长度的区别先有印象。
5. **帧率控制**：`QualitySettings.vSyncCount`与`Application.targetFrameRate`的关系。当前质量档开启了VSync，此时限帧设置会被忽略；编辑器Game视图也有VSync开关。

## 先写五行

```text
玩家输入是什么：玩家的输入是按键，也就是WASD。
移动速度放在哪里、单位是什么：基础移动速度放在配置文件里，然后游戏的类中应该有一个Runtime的速度值，这个会受到当前玩家情况的影响，单位是m/s。
输入如何变成世界位移：输入就是变成一个向量，然后这个向量乘以速度，每帧让受控的人物按照向量移动即可。
碰撞交给谁处理：碰撞交给碰撞盒处理，Unity自带的Collider，当然也有很多碰撞算法，比如AABB，SAF等
怎样验证斜向和帧率不会改变速度：斜向只需要保证在乘以速度的时候，这个向量被归一化了即可。帧率的话乘使用Time.deltaTime，这样都是一样的了。
```

## 输入读取方式（你来选，写进一页设计）

- 方式1：脚本里声明一个`InputAction`字段，在Inspector中配置WASD组合。文件最少，推荐首版使用。
- 方式2：建立`.inputactions`资产并生成C#类。多人输入和UI切换时更好管理，第3周做交互时再迁移也可以。Unity 6的Input System 1.13还支持“项目级动作”（Project-wide Actions），可以了解，但首周不必用。
- 首版不建议用PlayerInput组件，它的消息分发会引入额外概念。

## 实现顺序

1. 建立Move动作，类型为Vector2，配置WASD的2D Vector组合绑定。
2. 在Console打印四方向、斜向、W+S同按时读到的值，自己确认组合绑定是否已经处理斜向长度。
3. 在 `Assets/_Game/Scripts` 新建首个移动脚本，决定字段和函数怎样组织，再挂到Captain。
4. 按世界坐标约定实现：W为+Z、D为+X。
5. 通过CharacterController完成移动碰撞，当前平地练习保持出生高度。
6. 运行验收表，自己先定位并说明一个问题，再接受代码审查。
7. 自己提交Git（首版）。
8. **定位埋入的bug**：审查后，助手在你的代码里埋一个bug（只告诉你现象，不告诉位置），你按“现象→假设→检查→原因→修正”定位并修好。
9. **Shift奔跑**：独立完成需求变化，再提交一次。
10. **口述全流程**：从“按下W”讲到“船长在屏幕上移动、贴墙滑动”，覆盖输入、数据、每帧流程、碰撞与验证；助手模拟面试官追问。口述要点存入一页设计末尾。

首版可以只有一个小脚本。现代语法、模式数量和文件数量都不是验收指标。
